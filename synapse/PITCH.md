# Synapse — 人机混合团队的协作底座

---

## 电梯层（30 秒）

**每个开发者现在都在用 AI Agent 写代码——但没人管它们之间的协作。**

Claude Code 在改前端，Cursor 在改后端，Codex 在写测试。三个 Agent 各自为战，互相不知道对方在做什么。你在中间手工协调——"Claude 你等一下，Cursor 还没改完那个接口"。

**Synapse 就是管这个的。** 不存代码，不跑 CI/CD，不做即时通讯。只做一件事：让人类和 AI Agent 在同一个 Task 看板上对等协作。谁该做什么、做到哪了、能不能开始、做完了谁验证——这些协调工作从你的脑子里搬到平台上。

## 咖啡层（2 分钟）

### 为什么现有工具不够？

Jira、Linear、Notion 是为纯人类团队设计的。它们假设 Task owner 是人——人会自己理解模糊需求、会主动沟通、会对自己的产出负责。AI Agent 不会。你需要告诉它：这个 Task 依赖哪个 Task、验收标准是什么、谁有权判它通过——然后平台替你执行这些规则，不是替你写这些规则。

### Synapse 怎么做的？

**Task 是入口，其余都是标签。** 你创建一个 Task，填标题和描述就够了。Project、Batch、依赖关系——这些都是可选标签，需要时再加，不拦你。

**人和 Agent 在同一个看板上。** 你创建一个 Worker（人或 AI），给它一个角色——Orchestrator（拆任务 + 验收）或 Builder（执行任务）。Agent 通过 API Key 接入——和人类 OAuth 登录一样，都是这个看板上的对等参与者。

**状态机替你执行协作规则。** "没做完依赖项不能开始"、"没提交验证不能验收"——这些不是靠你盯着看板手工检查，是 API 层硬阻断。

### 一个典型的 Workflow

```
你（Orchestrator）创建 3 个 Task → 打包为一个 Batch
  → Builder Agent 拉取 Batch，逐个执行
  → 执行完成，Agent 提交验证
  → 你验收通过 → Task 关闭
  → 所有状态变更有完整审计 Event 可追溯
```

1 个人 + 2-3 个 AI Agent = 一个完整可交付单元。不需要更多角色，不需要更多流程。

## 晚餐层（需要时展开）

如果对方到这里还在问，说明真的感兴趣。以下是更深的东西：

### Agent 架构哲学

**两角色是终态，不是过渡。** Orchestrator（拆 + 验）+ Builder（执行）——这就是一个 2-pizza 团队的完整闭环。不需要第三个角色才能干活。

**三角色是规模化的自然分化。** 当多个 Workflow 并行跑时，跨项目的安全审计、规范一致性、绩效评估会从 Orchestrator 身上自然剥离，形成独立的 Steward（协理）角色——横向治理职能。这不是"加功能"，是需求拉动的自然演化。就像 Project 从 Task 标签变成独立实体一样——标签多到需要管理时，自然升级。

**组织嵌套硬上限 = 1 层。** Orchestrator 可以有下属 Builder，但 Builder 不能再有下属。复杂度增长靠工作流递归（上一层产出 = 下一层输入），不靠加深团队层级。

### 三个不妥协

1. **强制力在服务端，不在客户端。** Agent 可以偷懒，但在 API 上寸步难行——依赖没满足不能 claim、没提交验证不能验收。状态机是底线。
2. **角色分离 = 利益冲突外化。** 拆任务的人不执行，执行的人不验收。这是几百年组织设计的底层逻辑——不是 AI 才需要的。
3. **过程即资产。** 所有状态变更记录为不可变 Event。三个月后你能追溯"谁在什么时候做了什么决策"——这就是团队的 institutional memory，不靠人脑记忆。

### 技术骨架

- FastAPI (Python) + React (TypeScript/Vite) + SQLite/PostgreSQL
- 事件溯源审计链 + 乐观锁并发控制
- Worker 协议：Markdown 源文件 → 脚本适配 → 多客户端（Claude Code / Cursor / Codex）
- 当前：298 tests · 35 批次 · P9 产品主线开发中

## 如果对方说"听起来很复杂"

"复杂是因为协调本身就是复杂的。你现在脑子里管三个 Agent 的上下文切换、依赖关系、质量把关——这些复杂度已经在你脑子里了。Synapse 只是把它从你的短期记忆搬到屏幕上。用或不用，复杂都在——用的区别是，你不用一个人扛着。"

## 如果对方说"我只有一个 Agent，不需要"

"当你有第二个的时候，就已经需要了。两个 Agent 改同一个文件而你不在电脑前——那就是第一次协调事故。这个平台的意义不是等你有了 10 个 Agent 才用，是让你有 2 个 Agent 的时候不踩坑。"

## 如果对方说"这和 Jira 有什么区别"

"Jira 的 Task owner 字段是人名。你可以填 Agent 的名字进去——但 Jira 不知道 Agent 需要 API Key 认证、需要验证标准、需要考虑依赖就绪才能开始、需要 lease 超时自动释放。Jira 只是记录状态，Synapse 是在执行状态。你是记录者，Synapse 是协管者。"
